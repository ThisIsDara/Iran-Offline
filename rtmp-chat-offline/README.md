# RTMP Chat

Chat overlay for MediaMTX streams, plus a stream-key admin panel that decides
who is allowed to broadcast.

The target is an **offline Ubuntu 24.04 server**. Everything the runtime needs
is in this folder: Node.js, MediaMTX and the npm dependencies. Installing,
starting and managing the service never touches the network.

## One script

`rtmp-chat.sh` is the only command you need. On a fresh copy, this one command
verifies the bundle, installs Node/MediaMTX/dependencies, creates credentials
and config, installs both services and starts them:

```bash
sudo ./rtmp-chat.sh setup
```

`setup` is an alias for `install`; it uses systemd automatically when available
and falls back to PID-file mode otherwise. The commands below are optional
management and health checks, not extra setup steps:

```bash
sudo ./rtmp-chat.sh status              # mode, processes, health, admin URL
sudo ./rtmp-chat.sh logs                # journalctl (systemd) or logs/
sudo ./rtmp-chat.sh credentials         # admin URL + password
sudo ./rtmp-chat.sh restart
sudo ./rtmp-chat.sh doctor --full       # offline integrity + smoke test
```

Without systemd, use manual mode:

```bash
./rtmp-chat.sh install --manual
./rtmp-chat.sh start
./rtmp-chat.sh stop
```

`install.sh`, `manage.sh` and `start.sh` are thin compatibility wrappers around
the same script. New deployments should call `rtmp-chat.sh` directly.

```
rtmp-chat.sh              installer + service manager (offline)
server.js                 chat websocket + HTTP
lib/stream-keys.js        key store, admin API, MediaMTX publish gate
public/                   chat page + player (no external assets)
admin/                    admin panel UI, served only at the secret path
deps/                     offline bundle: Node, MediaMTX, node_modules
tools/build-bundle.sh     ONLINE ONLY: rebuild deps/
config/mediamtx.yml       generated by install
data/                     keys, admin password, admin URL (mode 700)
.runtime/                 unpacked Node/MediaMTX, state and saved env
```

## Install

From the repository root on the Ubuntu host, clone and install in one command:

```bash
git clone https://github.com/ThisIsDara/Iran-Offline.git && sudo ./Iran-Offline/rtmp-chat-offline/rtmp-chat.sh setup
```

If the repository is already on the machine (for example after copying it to an
air-gapped host), run the installer directly:

```bash
sudo ./rtmp-chat-offline/rtmp-chat.sh setup
```

Or from inside this directory:

```bash
sudo ./rtmp-chat.sh setup
```

Using `bash ./rtmp-chat.sh setup` also works if executable permissions were
lost while copying the folder.

`setup` never runs `apt`, `npm`, `curl`, `wget` or a DNS lookup. It:

1. verifies every archive in `deps/` against `SHA256SUMS` (`sha256sum -c`)
2. uses a bundled Node runtime, falling back to system Node only if needed
3. extracts `node_modules` and proves `express` and `ws` load
4. unpacks the bundled MediaMTX binary
5. writes `config/mediamtx.yml`, wired to this server for publish auth
6. creates `data/` (mode 700) and generates the admin password + secret URL
7. boots both programs once to prove the config is valid
8. installs `rtmp-chat.service` and `mediamtx.service` and starts them

If you omit `--systemd`, the installer picks systemd when it is available and
you are root/have sudo; otherwise it uses manual mode. Pass `--manual` to force
PID-file/log-file mode.

| | |
|---|---|
| Chat | `http://SERVER:8080/` |
| Admin | printed on install, also `./rtmp-chat.sh credentials` |
| Streamer | `rtmp://SERVER:1935/live/ROOM?key=STREAM_KEY` |
| Viewer | `http://SERVER:8888/live/ROOM/` |
| Health | `http://127.0.0.1:8080/healthz` |

### Install options

| | |
|---|---|
| `--systemd` | install and start systemd units (needs root/sudo) |
| `--manual`, `--no-systemd` | PID files + `logs/`, no systemd |
| `--port 9000` | chat HTTP/WebSocket port (default 8080) |
| `--rtmp-port` / `--hls-port` / `--webrtc-port` | move the MediaMTX ports |
| `--api-port` | MediaMTX control API on loopback (default 9997) |
| `--no-webrtc` | disable MediaMTX WebRTC (HLS keeps working) |
| `--no-mtx` | skip MediaMTX (only if you run your own) |
| `--data-dir DIR` | keys/credentials directory (default `./data`) |
| `--stream-base URL` | viewer base, e.g. `https://video.example.com` |
| `--rtmp-base URL` | streamer base, e.g. `rtmp://ingest.example.com/live` |
| `--force` | re-extract Node, node_modules and MediaMTX |
| `--no-verify` | skip the one-shot boot checks |
| `--no-start` | install but do not start anything |

`--data-dir` refuses `/`, the project folder, home directories, mount points
and system directories. This matters because `uninstall --purge` removes it.

## Manage

```bash
sudo ./rtmp-chat.sh start [chat|all]
sudo ./rtmp-chat.sh stop [chat|all]
sudo ./rtmp-chat.sh restart [chat|all]
sudo ./rtmp-chat.sh status
sudo ./rtmp-chat.sh logs [chat|all] [--no-follow]
./rtmp-chat.sh urls
./rtmp-chat.sh credentials
./rtmp-chat.sh doctor [--full]
./rtmp-chat.sh backup
./rtmp-chat.sh run [--with-mtx]        # foreground
```

`status` and `doctor` use `/healthz` and show the real admin URL (read from
`data/admin-path.txt`), not a guessable `/admin.html`.

Manual-mode logs live in `logs/chat.log` and `logs/mediamtx.log`. Systemd mode
uses `journalctl`. `logs` works in both modes.

## Uninstall

```bash
sudo ./rtmp-chat.sh uninstall          # keep data/
sudo ./rtmp-chat.sh uninstall --purge  # also remove data/, node_modules/, backups/
```

Services, `.runtime/`, `config/` and `logs/` are removed in both cases. The
default keeps stream keys and admin credentials so a reinstall is seamless.

## How the keys actually block streams

The chat server cannot stop an RTMP push on its own. MediaMTX asks it before
every publish, which is what the generated `config/mediamtx.yml` does:

```yaml
authMethod: http
authHTTPAddress: "http://127.0.0.1:8080/mediamtx/auth"

authHTTPExclude:
  - action: read
  - action: playback
  - action: api
  - action: metrics
  - action: pprof
```

Two things worth knowing:

- **Publishing fails closed.** If this server is down or unreachable, MediaMTX
  rejects every publish rather than letting anyone through.
- **Viewing fails open.** Every non-publish action is excluded above, so
  viewers keep watching even while the chat server restarts.

A publish is rejected when the key is missing, unknown, revoked, expired, or
bound to a different room.

> MediaMTX 1.x removed the old `globalHooks: runOnInit: "http://..."`
> mechanism and refuses to start with `ERR: json: unknown field
> "globalHooks"`. `authHTTPAddress` is the supported mechanism.

### Revoking

Revoking stops any **new** publish immediately. It cannot cut a stream that is
already running: MediaMTX only asks permission when a stream starts, and its
control API has no way to disconnect a publisher. The admin panel shows a
`LIVE` badge on a revoked key that is still connected so this is not a
surprise.

### Running MediaMTX elsewhere

Copy the generated block into that MediaMTX's `mediamtx.yml` with the right
host/port. The admin panel prints the exact snippet for the current settings.

## Admin panel

The panel is **not linked from the site and not at a guessable URL**. It is
served from `admin/` (outside the static folder) at a random path generated on
first run:

```
http://SERVER:8080/admin-<random>
```

Bookmark it. It is printed on install, logged at startup, saved in
`data/admin-path.txt`, and shown by `./rtmp-chat.sh credentials`. Set
`ADMIN_PATH` to pin your own. Deleting `data/admin-path.txt` mints a new one on
the next start.

This is a speed bump, not a lock - the real protection is the password and the
session token. Any URL can be found eventually, so do not treat it as
authentication.

Log in, create a key for a streamer, send it over. Keys can be bound to a
single room or `*` for any room, and can expire (7/30/90 days or custom) or be
revoked. The password comes from `ADMIN_PASSWORD`; if unset, one is generated
on first start and saved to `data/admin-password.txt`.

Streamers append the key to the **stream key**, not the URL:

```
OBS -> Settings -> Stream
  Server:    rtmp://YOUR_SERVER:1935/live
  Stream Key: arthas?key=sk_1a2b3c...
```

## Ports

| Port | What | Needed by |
|---|---|---|
| 1935 | RTMP | streamers |
| 8888 | HLS + web player | viewers |
| 8889 | WebRTC (optional) | viewers |
| 8080 | chat + admin + /healthz | viewers |
| 9997 | MediaMTX control API | loopback only |

```bash
sudo ufw allow 1935/tcp
sudo ufw allow 8888/tcp
sudo ufw allow 8080/tcp
# only if WebRTC is enabled:
sudo ufw allow 8889/udp
```

Do **not** expose 9997; the generated config binds it to `127.0.0.1`.

## Environment

The installer records the chosen values in `.runtime/install.env` and
`.runtime/env.sh`; `start`, `restart` and `run` reuse them. Re-run `install`
with options to change them.

| | Default | |
|---|---|---|
| `PORT` | `8080` | chat server |
| `STREAM_BASE` | derive from viewer host | where viewers watch |
| `RTMP_BASE` | derive from viewer host | where streamers push |
| `DATA_DIR` | `./data` | keys and password |
| `ADMIN_PASSWORD` | generated | admin login |
| `ADMIN_PATH` | random | secret URL for the admin panel |
| `STREAM_PORT` | `8888` | HLS/player port (from `--hls-port`) |
| `RTMP_PORT` | `1935` | RTMP port (from `--rtmp-port`) |
| `DEFAULT_STREAM` | `arthas` | room used when none is given |

Set `STREAM_BASE` only when viewers reach MediaMTX on a different host or port
(CDN/reverse proxy). Set `RTMP_BASE` only when streamers push to a different
hostname. Both are persisted for the service.

## Behind a CDN (Cloudflare, etc.)

RTMP **cannot go through an HTTP proxy.** Cloudflare proxies only HTTP(80,
8080, 8880, 2052, 2082, 2086, 2095) and HTTPS(443, 2053, 2083, 2087, 2096,
8443); anything else must be a **DNS-only** (grey cloud) record. The same is
true of every CDN. Spectrum would do it, but that is Enterprise-only.

So use two hostnames, and split them by protocol:

| | hostname | Cloudflare | port |
|---|---|---|---|
| chat + admin | `chat.example.com` | Proxied (orange) | 443 |
| video for viewers | `video.example.com` | Proxied (orange) | 443 |
| **RTMP ingest** | `ingest.example.com` | **DNS only (grey)** | 1935 |

In Cloudflare DNS, add all three A records pointing at the server IP. The two
orange ones must terminate TLS on 443 at the origin, so put a reverse proxy in
front of this app and route by hostname:

```
chat.example.com   -> 127.0.0.1:8080   (this server)
video.example.com  -> 127.0.0.1:8888   (MediaMTX)
```

Then tell the installer both bases, because they are genuinely different:

```bash
sudo ./rtmp-chat.sh install --systemd \
  --stream-base https://video.example.com \
  --rtmp-base rtmp://ingest.example.com:1935/live
```

Viewers get proxied HTTPS links; the admin panel's "Copy OBS setup" hands out
the grey-clouded ingest URL. Leave both unset and it still derives everything
from the host the viewer arrived on, which is right for a plain setup.

Notes:

- The grey-clouded record exposes your origin IP. That is the cost of RTMP.
- Add a Cloudflare **Cache Rule** to bypass `*.m3u8` and HLS segment paths, or
  stale playlists will be served from the edge.
- WebRTC (`:8889`) needs UDP and will not work through a proxy either. The
  player uses HLS by default, so leave WebRTC off or point it at the grey host.

See `CLOUDFLARE.md` for a longer walkthrough.

## Operations

Systemd mode:

```bash
sudo systemctl status rtmp-chat mediamtx
sudo systemctl restart mediamtx      # after editing config/mediamtx.yml
journalctl -u rtmp-chat -f
journalctl -u mediamtx -f
```

Manual mode:

```bash
./rtmp-chat.sh status
./rtmp-chat.sh restart all
./rtmp-chat.sh logs
```

Backups:

```bash
./rtmp-chat.sh backup
# backups/rtmp-chat-YYYYmmdd-HHMMSS.tar.gz contains config/ and DATA_DIR
```

## Testing

```bash
npm test          # 60+ checks, boots its own server on port 8099, no network
./rtmp-chat.sh doctor --full
```

To check the publish gate by hand, with `ffmpeg`:

```bash
# rejected
ffmpeg -re -i input.mp4 -c copy -f flv "rtmp://127.0.0.1:1935/live/arthas"
# accepted
ffmpeg -re -i input.mp4 -c copy -f flv "rtmp://127.0.0.1:1935/live/arthas?key=sk_..."
```

## Rebuilding the bundle

Only needed when a dependency or a bundled binary changes, and only on a
machine with internet:

```bash
./tools/build-bundle.sh              # Linux x64 + arm64
./tools/build-bundle.sh --all        # also the Windows Node runtime
./tools/build-bundle.sh --gz         # Node .tar.gz instead of .tar.xz
./download-deps.sh                   # compatibility wrapper
```

`tools/build-bundle.sh` is the only script allowed to use the network. It is
safe to carry it to the offline server; just never run it there. If `zip` is
installed it also refreshes `rtmp-chat-offline.zip` next to the project folder;
use `--no-zip` to skip that.

| In `deps/` (~113 MB) | Why |
|---|---|
| `node_modules.tar.gz` | express + ws and their transitive deps |
| `node-v24.12.0-linux-x64.tar.xz` | Node for x86-64 servers |
| `node-v24.12.0-linux-arm64.tar.xz` | Node for ARM servers |
| `mediamtx_v1.21.1_linux_amd64.tar.gz` | RTMP ingest + player |
| `mediamtx_v1.21.1_linux_arm64.tar.gz` | RTMP ingest + player |
| `SHA256SUMS` | verified by `rtmp-chat.sh` |

Only one architecture is extracted per install, so you can delete the unused
one before copying the bundle. Checksum verification uses `--ignore-missing`,
so the remaining files still validate.

## Notes

- `data/stream-keys.json` stores keys in plain text so you can re-copy them
  from the panel. It is written `chmod 600`. If keys ever leak, delete the file
  - all keys are invalidated.
- Chat history is in-memory only, cleared when the last person leaves a room
  or the server restarts.
- The chat UI has no external assets, fonts or CDNs. `server.js` sends a
  restrictive CSP plus `nosniff`/`no-referrer`/frame headers, and
  `./rtmp-chat.sh doctor` fails if an external URL appears under `public/` or
  `admin/`.
- `server.js` answers `/healthz` on loopback and shuts down cleanly on
  SIGTERM/SIGINT, so systemd restarts do not hang.
- The legacy `install.bat` / `manage.bat` / `start.bat` files are not part of
  the Ubuntu path. Use `rtmp-chat.sh`.
